# Book Service – система учета книг для чтения

## Назначение
Book Service – приложение для учета книг, которые пользователь читает, планирует прочитать или уже прочитал. Помогает отслеживать прогресс чтения и формировать персональный список литературы.

Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:
* просматривать список книг в браузере;
* просматривать информацию о конкретной книге (автор, год, статус, дата добавления);
* добавлять книги с указанием автора, года и статуса (консольная версия);
* фильтровать книги по статусам (консольная версия);
* искать книги по названию и автору (консольная версия);
* изменять статус книги по мере продвижения чтения (консольная версия);
* удалять книги из списка (консольная версия);
* сортировать книги по названию и году издания (консольная версия);
* просматривать статистику чтения (консольная версия);
* хранить данные между запусками приложения.

## Используемые технологии
* Python 3;
* Django 5.2 – веб-фреймворк;
* HTML – разметка веб-страниц;

## Целевая аудитория
Любой человек, который хочет отслеживать свои прочитанные книги.

## Предметная область
Предметная область – персональный учет книг для чтения. Пользователь ведет список книг, присваивая каждой статус:
* **Хочу прочитать** – книги, которые планируется прочитать;
* **Читаю** – книги, которые читаются в данный момент;
* **Прочитано** – завершенные книги;
* **Отложено** – книги, чтение которых приостановлено.

## Основные сущности

### Book – книга
Объект `Book` представляет книгу в списке чтения.

Основные атрибуты:
* `id` – уникальный идентификатор книги;
* `title` – название;
* `author` – автор;
* `year` – год издания;
* `status` – статус чтения;
* `date_added` – дата добавления.

Основные методы:
* `set_status()` – установка нового статуса;
* `is_read()` – проверка, прочитана ли книга;
* `matches_query()` – проверка совпадения с поисковым запросом;
* `to_dict()`, `from_dict()` – преобразование в словарь и обратно (для JSON);
* `validate()` – проверка данных книги;
* `__str__()`, `__repr__()` – строковые представления.

### User – пользователь
Объект `User` представляет пользователя системы.

Основные атрибуты:
* `id` – уникальный идентификатор пользователя;
* `name` – имя пользователя;
* `created_at` – дата регистрации.

Основные методы:
* `update_name()` – изменение имени;
* `to_dict()`, `from_dict()` – преобразование в словарь и обратно;
* `__str__()`, `__repr__()` – строковые представления.

### BookList – список книг пользователя
Объект `BookList` хранит коллекцию объектов `Book` и содержит логику работы с ней: `add()`, `find_by_id()`, `find()`, `filter_by_status()`, `sort_by_title()`, `sort_by_year()`, `change_status()`, `remove()`, `get_statistics()`.

### Status – статус чтения
Перечисление `Status`: `WANT_TO_READ` (хочу прочитать), `READING` (читаю), `READ` (прочитано), `ON_HOLD` (отложено).

## Страницы веб-интерфейса
* `/` – главная страница: описание приложения и навигация (view-функция `index()`);
* `/books/` – список книг: объекты `Book` из `data/books.json` (view-функция `books()`);
* `/books/<int:book_id>/` – страница книги (view-функция `book_detail()`).

Если книга с указанным идентификатором не найдена, страница книги возвращает код статуса 404. Для несуществующих адресов используется собственная страница 404 (`handler404`, view-функция `page_not_found()`).

## Основные операции

### Используется в веб-интерфейсе (ПР5)
* просмотр списка книг;
* просмотр информации о книге;
* отображение статуса чтения и признака «прочитана» (`Book.is_read()`).

### Отложено до следующих работ
Эти операции реализованы в ПР3 и работают в консольной версии. В веб-интерфейсе они появятся, когда будут добавлены формы и POST-запросы:
* добавление книги;
* изменение статуса книги;
* удаление книги;
* поиск книги по названию и автору;
* фильтрация по статусу;
* сортировка книг;
* статистика чтения.

## Хранение данных
Данные приложения хранятся в JSON-файлах:
* `data/books.json`;
* `data/users.json`.

При загрузке данные из JSON преобразуются в объекты `Book` и `User`. При сохранении объекты преобразуются в данные JSON.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3). Отвечает за запуск консольного приложения, отображение меню, получение данных от пользователя и организацию пользовательских сценариев.

### `book_service/`
Пакет настроек Django-проекта:
* `settings.py` – настройки проекта (`INSTALLED_APPS`, `ALLOWED_HOSTS`, язык и часовой пояс);
* `urls.py` – маршрутизация верхнего уровня и `handler404`;
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`
Django-приложение, отвечающее за главную страницу:
* `views.py` – функция `page()` (общий HTML-каркас), view-функции `index()` и `page_not_found()`;
* `urls.py` – маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задает общий вид всех остальных страниц – она точка входа в проект. Остальные приложения импортируют ее.

### `books/`
Django-приложение, отвечающее за книги:
* `views.py` – view-функции `books()` и `book_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

### `models/`
Классы предметной области и функции работы с ними (пакет ПР3): `book.py` – класс `Book`, `book_list.py` – класс `BookList`, `user.py` – класс `User`, `status.py` – перечисление `Status` и вспомогательные функции статусов.

### `storage.py`
Загрузка и сохранение данных: JSON → объекты Python, объекты Python → JSON.

### `utils.py`
Вспомогательные функции консольного ввода: `input_int()`, `input_non_empty()`, `input_date()`, `input_status()`.

### `tests/`
Автоматизированные тесты проекта (pytest).
